# pdf2md

Convert academic PDF papers to clean, publication-quality markdown. Extracts vector figures at high resolution, reconstructs LaTeX equations, generates VLM-powered figure descriptions, and produces properly structured documents with linked citations and embedded figures.

## What It Does

**pdf2md** takes a PDF academic paper and produces:

1. **Clean Markdown** with proper section hierarchy (`##`/`###`/`####`), linked citations, and embedded figures
2. **High-Resolution Figures** rendered from vector graphics (charts, diagrams, flowcharts) as PNGs
3. **VLM Figure Descriptions** generated by a vision language model for each figure
4. **Reconstructed LaTeX Equations** from garbled PDF unicode
5. **Extracted Tables** using PyMuPDF's built-in table detector
6. **RAG-Ready JSON** with figures, equations, and tables as structured data

## Quick Start

```bash
# Install
uv sync --all-extras

# Basic conversion (medium depth: extraction + postprocess + LLM retouch)
uv run pdf2md convert paper.pdf ./output

# Fast conversion (no AI, rule-based only)
uv run pdf2md convert paper.pdf ./output -d low

# Full pipeline with local LLM + VLM
LM_STUDIO_HOST=http://localhost:1234/v1 \
PDF2MD_TEXT_MODEL=nemotron-cascade-2-30b-a3b-i1 \
PDF2MD_VLM_HOST=http://localhost:8081/v1 \
PDF2MD_VLM_MODEL=qwen3-vl-30b \
uv run pdf2md convert paper.pdf ./output -d high --local
```

## Pipeline Architecture

```
PDF
 ├─ PyMuPDF: text per page, vector figures rendered at 200 DPI, tables    (instant)
 ├─ Postprocess: citations, sections, figures, bibliography, cleanup      (instant)
 ├─ LLM Retouch: author formatting, lettered sections                     (1-2 calls)
 ├─ VLM: figure descriptions for each extracted figure                    (per figure)
 └─ Synthesis: equation reconstruction, garbled unicode cleanup, integration
      └─ Output: clean markdown + figures.json + tables.json + equations.json
```

No local ML models. No CPU tensors. All inference runs on remote LLM/VLM endpoints.

## Depth Levels

| Depth | What Runs | Speed |
|-------|-----------|-------|
| `low` | PyMuPDF extraction + rule-based postprocessing | Instant, no AI |
| `medium` | + LLM retouch (author formatting, lettered sections) | ~30s |
| `high` | + VLM figure descriptions + synthesis pass (equations, cleanup) | ~5 min |

## Commands

### `pdf2md convert`

Main conversion command. Runs the full pipeline.

```bash
uv run pdf2md convert paper.pdf ./output [OPTIONS]
```

**Core Options:**

| Option | Description |
|--------|-------------|
| `-d, --depth` | `low`, `medium` (default), `high` |
| `-l, --local` | Use local LLM/VLM endpoints instead of Claude cloud |
| `-p, --provider` | `lm_studio` (default) or `ollama` |

**Feature Flags:**

| Option | Description |
|--------|-------------|
| `--no-vlm` | Skip VLM figure descriptions (faster `high` runs) |
| `--synthesis/--no-synthesis` | Enable/disable synthesis pass (default: enabled at high) |
| `--keep-raw` | Save raw extraction alongside processed output |
| `--raw` | Skip all processing, output raw PyMuPDF text only |

**Model Options:**

| Option | Description |
|--------|-------------|
| `-m, --model` | Override text LLM model for retouch/synthesis |
| `--vlm-model` | Override VLM model for figure descriptions |
| `--text-endpoint` | Override text LLM endpoint URL |
| `--vlm-endpoint` | Override VLM endpoint URL |

**Image Options:**

| Option | Default | Description |
|--------|---------|-------------|
| `--images-scale` | 2.0 | Rendering DPI multiplier for figure capture |
| `--min-image-width` | 200 | Minimum figure width in pixels |
| `--min-image-height` | 150 | Minimum figure height in pixels |
| `--min-image-area` | 40000 | Minimum figure area in pixels |

**Output Structure:**

```
output/paper-name/
├── paper-name.md           # Final processed markdown
├── paper-name_raw.md       # Raw extraction (if --keep-raw)
├── img/
│   ├── figure1.png         # Rendered vector figures at 200 DPI
│   ├── figure2.png
│   └── ...
├── figures.json            # VLM descriptions (depth=high)
├── tables.json             # Extracted tables as markdown
└── equations.json          # Reconstructed LaTeX equations
```

### `pdf2md retouch`

Run LLM-based cleanup on an existing markdown file.

```bash
uv run pdf2md retouch paper.md --local
```

Fixes author formatting and lettered section headers using LLM judgment.

### `pdf2md postprocess`

Run rule-based post-processing only (no AI).

```bash
uv run pdf2md postprocess paper.md
```

Applies citations, sections, figures, bibliography, and cleanup deterministically.

### `pdf2md enrich`

Extract RAG metadata from a PDF using Docling.

```bash
uv run pdf2md enrich paper.pdf ./output --describe --local
```

Produces structured JSON with code blocks, equations, and figure metadata.

## Processing Details

### Figure Extraction

Figures are extracted by locating "Figure N:" captions in the text, then rendering the page region above each caption at high resolution (200 DPI). This captures vector graphics (charts, diagrams, heatmaps) that are invisible to raster-only extraction. Decorative icons, logos, and axis labels are automatically excluded.

### Citation Handling

- Single citations: `[7]` becomes `[[7]](#ref-7)` (clickable link)
- Ranges: `[6-11]` or `[6]-[11]` expand to individual linked citations
- Line-break ranges: `[6–\n11]` are rejoined before expansion
- Reference anchors: `<a id="ref-N"></a>` added to bibliography entries

### Section Hierarchy

Detects numbered sections in PDF text (including split-line patterns like `1\nIntroduction`) and converts them to proper markdown heading levels:

- `1 Introduction` becomes `## Introduction`
- `2.1 Background` becomes `### 2.1 Background`
- `3.2.1 Energy Model` becomes `#### 3.2.1 Energy Model`

### Math Degarbling

PDF math fonts use codepoints in the Mathematical Alphanumeric Symbols block (U+1D400-U+1D7FF). Some extractors truncate these to Hangul syllables (U+D400-U+D7FF). The cleanup pass maps them back to plain ASCII, then the synthesis pass sends remaining garbled sections to the LLM for LaTeX reconstruction.

### Synthesis Pass

At `depth=high`, the synthesis pass:

1. Detects equation regions (high concentration of math unicode)
2. Sends garbled equations to the LLM for LaTeX reconstruction
3. Programmatically fixes section hierarchy
4. Inserts VLM figure descriptions as invisible HTML comments after figure images
5. Removes `<!-- formula-not-decoded -->` placeholders
6. Sends sections with remaining garbled unicode to the LLM for cleanup
7. Preserves every character of original text (edit-based, not regenerative)

## Local AI Setup

pdf2md supports two-endpoint configurations: a text LLM for retouch/synthesis and a VLM for figure descriptions. These can run on different machines.

```bash
# Text LLM on one machine, VLM on another
export LM_STUDIO_HOST=http://192.168.86.143:1234/v1
export PDF2MD_TEXT_MODEL=nemotron-cascade-2-30b-a3b-i1
export PDF2MD_VLM_HOST=http://192.168.86.141:8081/v1
export PDF2MD_VLM_MODEL=qwen3-vl-30b

uv run pdf2md convert paper.pdf ./output -d high --local
```

Or override endpoints directly on the CLI:

```bash
uv run pdf2md convert paper.pdf ./output -d high --local \
  --text-endpoint http://host1:1234/v1 \
  --vlm-endpoint http://host2:8081/v1
```

### Environment Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `PDF2MD_TEXT_MODEL` | `qwen3-4b` | Text LLM model name |
| `PDF2MD_VLM_MODEL` | `qwen3-vl-4b` | VLM model name |
| `PDF2MD_PROVIDER` | `lm_studio` | Default provider |
| `LM_STUDIO_HOST` | `http://localhost:1234/v1` | Text LLM endpoint |
| `PDF2MD_VLM_HOST` | `http://localhost:1234/v1` | VLM endpoint |
| `OLLAMA_HOST` | `http://localhost:11434` | Ollama endpoint |

### Local AI Notes

- `--local` defaults to LM Studio unless `--provider` or `PDF2MD_PROVIDER` is set.
- Text and vision endpoints are independent. Use `LM_STUDIO_HOST` for retouch/synthesis and `PDF2MD_VLM_HOST` for figure descriptions.
- If the default model names are left in place, pdf2md queries `/v1/models` and prefers a loaded Nemotron text model or a loaded VLM model when the endpoint exposes one.
- High-depth figure descriptions are intentionally long. The VLM call allows larger responses and a longer timeout so thinking VLMs can finish exhaustive chart/diagram descriptions.
- Thinking tags are stripped from final figure descriptions. If a thinking model emits only an unclosed `<think>` block before hitting its token limit, pdf2md keeps the useful text instead of returning an empty caption.
- In the homelab setup, the tested endpoints are `http://192.168.86.143:1234/v1` for Nemotron text work and `http://192.168.86.141:8081/v1` for Qwen3-VL figure descriptions.

## Installation

```bash
# Full installation (recommended)
pip install pdf2md[all]

# Or with uv
uv sync --all-extras

# Selective installation:
pip install pdf2md[agent-local]   # Local LLM backend (LiteLLM)
pip install pdf2md[agent]         # Claude cloud backend
pip install pdf2md[docling]       # Docling for enrich command
pip install pdf2md[dev]           # pytest + ruff
```

### Requirements

- Python 3.10-3.12
- PyMuPDF (included in base install)
- For `depth=medium` or `depth=high`: LiteLLM + an LLM endpoint
- For VLM descriptions: a vision-language model endpoint
